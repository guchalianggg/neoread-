## 剩余限制与工作反思

- **没有阻塞项。** 本次已满足约定的本机 Radmin 地址与两个独立客户端验收；未操作另一台实体电脑，未重启整个 Windows，也未运行 NeoRead 完整 GUI。打包测试包含正常重启、强制进程丢失、自启参数、恢复、停止不恢复及并发单实例，不把这些声称为实体对端/真实重启验收。
- **现在最没把握的是什么？** 真实对端自身的 VPN 路由、防火墙和证书环境没有观测证据，不能由服务器本机测试推断。对端可执行下方无凭据 TLS 命令；本次未远程修改其环境。
- **用户最大的盲区是什么？** 平等门户意味着任何访问者都能撤销其他人的 Key；来源 IP 是观察到的连接，不是账户身份或 VPN 成员名册。此设计正是批准范围，不应当作私有账户权限系统。参见 README 第十二、十三节，以及 `portal_ui.py` 的 Key 自助说明与在线设备说明。
- 统计从升级开始，不回填历史；明细仅 30 天、每次页面最近 100 条；清理后的历史筛选为重叠小时粒度。已知 Token 是上游实际字段的已知部分之和，不推测缺失字段，也不估算费用。
- 默认 Web/EXE 提供门户统计；旧 Tk/headless 模式保持转发兼容但不初始化统计门户。旧 CA 缺少某些扩展，Python 3.13 可选严格 X.509 策略可能拒绝它；没有为满足该额外策略而轮换已信任根。Windows/Chrome 实际检查已通过。
- 32 连接、8 API 槽位为桥接资源上限，不代表后端保证 8 路推理吞吐，也不限制只能登记两台设备。系统防火墙、系统信任与无关文件未变更。

对端仅检查网络与系统 TLS（无 Key，不发推理）：

```powershell
Test-NetConnection 26.236.3.200 -Port 8443
curl.exe --noproxy "*" --max-time 10 --ssl-revoke-best-effort -v https://26.236.3.200:8443/cert -o NUL
```

根证书未信任时，按 README 第十一节在该设备核对固定指纹并安装；日常 API 不关闭 TLS 校验。
